# Обновление до этапа 4 — мероприятия (Windows / VS Code)

## 1. Сохраните настройки и замените исходники

Остановите сайт в терминале через **Ctrl+C**. Docker Desktop оставьте запущенным.

Распакуйте архив во временную папку. Скопируйте **содержимое** папки studentconnect из архива в прежнюю папку studentconnect с заменой исходников. Не создавайте вложенную studentconnect/studentconnect. Сохраните свои `.env` в корне, apps/api и apps/web. В архиве настоящих `.env` нет. Если меняли compose.yaml, сохраните свои параметры базы.

## 2. Откройте терминал в прежней папке studentconnect

Выполняйте каждую команду отдельно и дожидайтесь успеха. При ошибке следующие команды не вводите.

```powershell
npm.cmd ci
```

```powershell
npm.cmd run db:generate
```

```powershell
docker compose up -d --wait
```

**Новая миграция обязательна:**

```powershell
npm.cmd run db:migrate
```

```powershell
npm.cmd run db:seed
```

```powershell
npm.cmd run dev
```

Откройте http://localhost:5173 и войдите в существующий аккаунт. Данные не сбрасываются. Ожидаемая версия package.json — 0.4.0.

Если отсутствуют настройки, создайте только недостающие файлы (не заменяйте существующие):

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
if (!(Test-Path apps/api/.env)) { Copy-Item apps/api/.env.example apps/api/.env }
if (!(Test-Path apps/web/.env)) { Copy-Item apps/web/.env.example apps/web/.env }
```

Затем повторите запуск Docker, миграции и seed. Если прежде меняли пароль, используйте ваши прежние настройки: пароль в .env не меняет пароль уже существующего Docker-тома.

## 3. Проверьте обычное участие

1. Первый аккаунт: «Мероприятия» → «Создать мероприятие». Выберите будущую дату, категорию, место и вместимость 2. Организатор занимает одно место.
2. Второй аккаунт в инкогнито: откройте это мероприятие и подайте заявку.
3. Первый аккаунт: обновите детали кнопкой со стрелкой и примите заявку. В составе должно быть 2 из 2, свободных мест — 0.
4. Второй аккаунт: обновите детали и выйдите. Подтвердите выход.
5. Подайте заявку снова, примите её первым аккаунтом. Это второе успешное вступление.
6. Выйдите вторым аккаунтом ещё раз. Третье вступление в это мероприятие должно быть запрещено.

## 4. Проверьте исключение отдельно

Создайте другое мероприятие, примите второго пользователя и исключите его с причиной. Второй пользователь должен увидеть причину и запрет повторного вступления. В первом и втором мероприятиях счётчики независимы.

## 5. Проверьте уведомления

В разделе «Мероприятия» разверните «Уведомления мероприятий». Организатор получает заявки, участник — результат и причину исключения. Пока открыт раздел, обновление происходит каждые 30 секунд; можно нажать ручное обновление. Отметка прочитанным действует только для своего аккаунта.

Полноценный чат ещё не реализован. После начала мероприятия изменение состава закрыто. Редактирование и удаление мероприятий пока недоступны.

## Проверки разработчика

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```

Автотесты по умолчанию используют собственную временную PostgreSQL WASM-базу, не вашу рабочую БД. Проверка одновременных HTTP-запросов проходит в одном SQL-соединении; реальную многосоединительную гонку следует проверить отдельно (режим описан в README).
