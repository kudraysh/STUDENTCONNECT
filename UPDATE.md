# StudentConnect 0.9.0 — подготовка публикации

Главная новая инструкция — DEPLOY.md. Подготовлены единый сервер сайта/API/чата, Render Free, Neon PostgreSQL и настоящие письма через Brevo HTTPS API. Никакого отключения подтверждения почты для публичного запуска.

## Если продолжаешь локальную проверку

Останови сайт Ctrl+C, скопируй новые исходники поверх проекта, сохрани все .env, node_modules и Docker-том. Зависимости не менялись, npm.cmd ci повторять не нужно, если версия 0.8.0 уже работала. Новых SQL-миграций в этапе 9 нет.

В apps/api/.env локально оставь NODE_ENV=development, SERVE_WEB=0 и MAIL_MODE=console. Для текущего ngrok задай действующий домен:

```powershell
$env:TRUST_PROXY="1"
$env:WEB_ORIGIN="https://ВАШ-ТЕКУЩИЙ-ДОМЕН.ngrok-free.app"
$env:__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS="ВАШ-ТЕКУЩИЙ-ДОМЕН.ngrok-free.app"
npm.cmd run dev
```

При запуске только localhost используй WEB_ORIGIN=http://localhost:5173. Не копируй production-настройки поверх рабочего локального .env и не меняй прежний пароль базы.

## Публикация

1. Код должен быть в GitHub целиком, включая apps/ и миграции; node_modules/.env/дампы не публикуются. Подготовлен существующий репозиторий kudraysh/STUDENTCONNECT, старый main был версии 0.4.0.
2. Создан новый бесплатный проект Neon studentconnect во Frankfurt. Это отдельная пустая облачная база, данные с компьютера не переносятся автоматически.
3. В Render нужен Free-сервис в выбранном рабочем пространстве, параметры из render.yaml и DEPLOY.md. До подтверждения пространства/создания сервиса постоянная ссылка не считается готовой.
4. В Brevo нужно зарегистрироваться, подтвердить отправителя и активировать транзакционную отправку. API key вводится только в Render Environment, не в чат или GitHub.
5. После ввода секретов и успешного deploy проверяем /api/ready, настоящую регистрацию/письмо и чат с телефона. Только тогда можно выключать компьютер и показывать публичный адрес преподавателю.

Команда npm.cmd run test:production предназначена для разработчика: она собирает проект и проверяет production-сервер в изолированной локальной БД. Это не размещение в интернете.
