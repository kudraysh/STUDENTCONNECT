# StudentConnect 0.9.0 — бесплатное размещение

Схема для демоверсии: один Node.js-сервис Render Free (React-сборка + Express + Socket.IO), PostgreSQL Neon Free и подтверждение почты через HTTPS API Brevo Free. Это рекомендуемый первый вариант. Отдельный Vercel-проект не нужен: единый HTTPS-адрес избегает межсайтовых cookie в Safari и сложной настройки WebSocket-прокси. Собственный домен покупать для адреса сайта не требуется.

Исходный код: https://github.com/kudraysh/STUDENTCONNECT . Используется существующий репозиторий, старая версия остаётся в истории Git. Секреты, node_modules, сборки и дампы не включаются в исходники. Исторический локальный .env из старой загрузки удаляется из актуального дерева; настройки хостинга вводятся только в Render.

## 1. База Neon

В подключённой бесплатной организации создан отдельный проект:

- Имя: studentconnect
- Project ID: floral-cell-35740634
- Регион: AWS Frankfurt (aws-eu-central-1)
- PostgreSQL: 17
- База: studentconnect
- Ветка: production (используйте фактическую default-ветку проекта, не угадывайте branch ID)
- Compute: 0.25 CU, тариф организации Free; автоматический сон определяется бесплатным тарифом.

Эта база изначально пустая. Первый запуск Render применит все миграции и создаст справочники. Он **не копирует** аккаунты/переписку с вашего компьютера. Локальная Docker-база остаётся без изменений; для первого показа в интернете зарегистрируйте тестовые аккаунты заново. Перенос реальных локальных данных — отдельная операция с резервной копией.

Если настройки выполняет ассистент через Neon/Render, DATABASE_URL передаётся между подключёнными сервисами без публикации. При ручной настройке откройте https://console.neon.tech → проект → Connect, выберите базу studentconnect, отключите Connection pooling и скопируйте прямую строку подключения. Вставьте её в секрет DATABASE_URL в Render. Не присылайте строку в чат и не добавляйте в GitHub.

Оставьте sslmode=require. Для маленького одного сервера можно добавить параметры connection_limit=5, connect_timeout=30, pool_timeout=30, сохранив остальные параметры URI. Если URI уже содержит ?, новые параметры добавляются через &, а не второй ?. Никаких тестовых локальных паролей для облачной базы.

## 2. Настоящие письма Brevo

На Render Free заблокированы SMTP-порты 25/465/587. Поэтому здесь используется MAIL_MODE=brevo, то есть HTTPS на порту 443. Рабочие варианты SMTP сохранены для других хостингов; console разрешён только локально.

1. Создайте бесплатный аккаунт https://www.brevo.com/ . Выберите Free, не подключайте платный тариф для этой инструкции.
2. В аккаунте откройте Settings → Senders, Domains, IPs → Senders → Add a sender.
3. Имя отправителя — StudentConnect. Адрес — принадлежащая вам почта. Подтвердите её кодом из письма. Не указывайте noreply@studentconnect.local.
4. Убедитесь, что в аккаунте активна отправка транзакционных писем. Brevo может запросить проверку аккаунта; до её завершения доставка не гарантируется.
5. В SMTP & API → API Keys создайте API v3 key. Это **API key**, не SMTP password.
6. Сохраните ключ только в переменной BREVO_API_KEY в Render Environment. Адрес подтверждённого отправителя — BREVO_SENDER_EMAIL. Ключ не отправляйте в чат, GitHub или frontend.

Бесплатный тариф Brevo на дату подготовки включает до 300 писем в сутки. Без собственного почтового домена провайдер может заменять домен отправителя на brevosend.com и/или предупреждать о DKIM/DMARC. Возможность отправки зависит от проверки аккаунта/отправителя и правил провайдера. Для устойчивой настоящей эксплуатации понадобится собственный аутентифицированный домен. Для демо сначала подтвердите успешную доставку на реальные адреса тестировщиков; не обходите подтверждение почты в базе.

Если письма нет: проверьте Spam, статус отправителя, transactional-активацию, API key, лимит и журналы Brevo. Аккаунт в приложении сохраняется, повторная отправка доступна через минуту. Ошибки провайдера и ссылки с токенами не печатаются в production-логи.

## 3. Render Free

Код должен быть в корне репозитория: package.json рядом с apps/ и render.yaml. Root Directory оставьте пустым.

При создании из Blueprint Render читает render.yaml. При ручном создании New → Web Service задайте:

| Поле | Значение |
|---|---|
| Repository | kudraysh/STUDENTCONNECT |
| Branch | main (или подготовленная ветка релиза, если выбрана отдельно) |
| Runtime | Node |
| Region | Frankfurt |
| Instance type | Free |
| Build Command | npm ci --include=dev && npm run db:generate && npm run build |
| Start Command | npm run deploy:start |
| Health Check | /api/health |
| Root Directory | пусто |

Не выбирайте платный Starter или платную базу Render. Если интерфейс требует платный тариф/оплату, остановитесь и уточните условия. Согласованный бюджет — бесплатный вариант.

Переменные Environment (пример без секретов — deploy/production.env.example):

| Переменная | Значение |
|---|---|
| NODE_VERSION | 24 |
| NODE_ENV | production |
| SERVE_WEB | 1 |
| TRUST_PROXY | 1 |
| COOKIE_SAME_SITE | lax |
| VITE_API_URL | пустая строка |
| MAIL_MODE | brevo |
| BREVO_SENDER_NAME | StudentConnect |
| DATABASE_URL | секрет Neon |
| BREVO_API_KEY | секрет API Brevo |
| BREVO_SENDER_EMAIL | ваша подтверждённая почта отправителя |

WEB_ORIGIN можно не задавать: при NODE_ENV=production и SERVE_WEB=1 приложение использует служебный RENDER_EXTERNAL_URL. Это адрес сервиса Render, а не произвольный заголовок запроса. Если WEB_ORIGIN задан явно, он имеет приоритет и должен точно совпадать с вашим HTTPS-адресом сайта без пути/параметров. Старый ngrok-адрес в облачном сервисе не используйте.

PORT назначается Render — не фиксируйте его вручную. Node.js слушает 0.0.0.0. TRUST_PROXY=1 предназначен для этого единственного прокси; не переносите настройку вслепую на другую инфраструктуру.

При создании сервиса через подключённый Render требуется явно выбранное рабочее пространство. В аккаунте найдено My Workspace; перед записью туда нужно подтвердить выбор. Создание сервиса и готовый публичный сайт — разные состояния: пока секреты Brevo не заданы, приложение намеренно не запускается. Ошибка о BREVO_API_KEY означает, что нужно завершить Environment, а не отключить проверку почты.

Start Command сначала выполняет prisma migrate deploy и повторяемый seed справочников, затем запускает собранный сервер. Free не требует отдельного платного pre-deploy job. Dev-зависимости нужны для Prisma CLI и seed; не удаляйте их после build. На стадии build миграции не запускаются. При изменении main Render с auto-deploy сам запускает обновление, вручную дублировать deploy не нужно.

## 4. Проверка после первого успешного deploy

1. Откройте реальный адрес из Render, не предполагаемый адрес по имени сервиса.
2. /api/health должен вернуть status=ok, /api/ready — database=connected.
3. Зарегистрируйтесь, получите настоящее письмо, откройте ссылку и подтвердите аккаунт.
4. Выйдите/войдите; убедитесь, что cookie устанавливается через HTTPS. Пароли и cookie не храните в localStorage.
5. Друг регистрируется на той же ссылке. Проверьте сообщение в обе стороны, обновление страницы диалога, телефон, уведомления и ленту.
6. Откройте /people/feed или /messages/<id> прямой ссылкой и обновите браузер: SPA-страница должна открыться без серверного 404. API-404 и отсутствующие JS-файлы не превращаются в HTML.
7. После перезапуска/сна данные остаются в Neon. Фотографии хранятся в БД, не на временном диске Render.
8. Проверьте с телефона Safari/Chrome. Локальная автоматическая проверка не подтверждает всю цепочку Render → Neon → Brevo в вашем аккаунте.

Внешняя база не заполняется фальшивыми пользователями с общим паролем. Локальные изолированные тестовые аккаунты не переносятся.

## 5. Ограничения бесплатной демоверсии

- Render Free засыпает после 15 минут без входящего трафика. Первый запрос после сна может ждать около минуты. Не запускайте искусственные keep-alive-пинги ради обхода ограничений.
- Render Free имеет лимиты времени, исходящего трафика и build minutes; квоты/поведение могут измениться. Проверьте Dashboard и условия перед включением платёжных данных.
- Render Free Postgres истекает через 30 дней; в этой схеме он не используется.
- Neon Free имеет квоты вычислений/хранилища/трафика и автоматический сон. При их исчерпании демо может стать недоступным, платный тариф автоматически не согласован.
- Brevo Free имеет суточный лимит и собственные проверки отправителя/аккаунта; бесплатный тариф не гарантирует доставку в Inbox.
- Один Node.js-процесс без Socket.IO-adapter и общего rate-limit store. Горизонтальное масштабирование не настроено.
- Приложение и фото живут в базе, но резервные копии пользовательских данных/длительное хранение остаются отдельной задачей. Не полагайтесь на бесплатные тарифы как на единственную копию ценных данных.

## 6. Техническая проверка без облачных секретов

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:production
```

Последняя команда собирает web/API и запускает настоящий собранный сервер на случайном локальном порту с отдельной PGlite-базой. Проверяет SPA deep link, readiness, Secure/HttpOnly-cookie, авторизованный API и сообщение через Socket.IO. Настоящие письма не отправляются, ваша Docker/Neon-база не меняется. Проверки Mailer используют поддельный fetch для HTTP API, а не действующий Brevo.
