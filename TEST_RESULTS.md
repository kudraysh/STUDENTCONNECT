## Найдено и исправлено

1. Первый полный прогон обнаружил зависание проверки страниц уведомлений: курсор возвращался к той же странице, если часовой пояс базы отличался от UTC. Date-параметр RAW SQL приводился через TimeZone PostgreSQL. Теперь используется явный UTC ISO timestamp и сравнение пары (createdAt,id). Дополнительно исправлено сравнение даты скрытия в ленте. Проверки принудительно устанавливают Europe/Moscow; пагинация и срок пропуска проходят. Цикл теста ограничен, чтобы повторная регрессия давала быструю ошибку.
2. Небезопасное чтение/запись localStorage при настройке темы могло обрушить приложение в браузере, запретившем хранилище. Ошибки теперь перехватываются, тема работает в текущей вкладке. Это найденный риск в коде, не доказанная причина прежнего белого экрана пользователя.
3. Браузеры без randomUUID не могли отправить сообщение. Добавлен UUID v4 через crypto.getRandomValues без Math.random. Эта же функция используется формой отчётов.
4. Для ошибок рендеринга React добавлена страница восстановления. Она не заменяет диагностику сетевой загрузки JavaScript и отдельно в реальном браузере не испытывалась.

После исправления пункта 1 выполнен новый полный прогон; итоговые 107 проверок прошли. Ранние неуспешные результаты не считаются успешной проверкой релиза.

## Границы достоверности

- База тестов — PostgreSQL WASM PGlite через TCP, с одним соединением. Параллельные HTTP-запросы проверены, однако блокировки между несколькими настоящими PostgreSQL-соединениями и нагрузка не подтверждены. Опциональный EVENT_TEST_DATABASE_URL в этом прогоне не использовался.
- Socket.IO проверяется настоящими Node.js-соединениями polling/WebSocket. Полная цепочка Windows → браузер → ngrok → Vite → API вручную здесь не проверялась.
- Проверки вспомогательных функций выполняются в Node.js. Это не браузерное E2E-тестирование и не подтверждение всех версий Safari.
- SMTP, публичный хостинг и настоящий системный push не проверялись; тесты используют изолированные аккаунты и почтовые заглушки.
- Пользователь ранее подтвердил работу сообщений, уведомлений, ленты/свайпов и открытия сайта на телефоне в версиях до 0.8.0. Это не заменяет повторную ручную проверку новой формы и полного чек-листа.
- Одновременный ручной прогон 3–5 тестировщиков ещё не выполнен. Для него подготовлен TESTING.md с 29 сценариями и незаполненными результатами.

Итог: код и автоматическая часть этапа 8 подготовлены; окончательная ручная приёмка демоверсии остаётся за тестировщиками. Публикация (этап 9) в эту работу не входит.
