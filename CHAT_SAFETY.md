# StudentConnect 0.10.0 — чат и жалобы

## Обновление

1. Останови локальный npm run dev (Ctrl+C), если он запущен.
2. Распакуй архив обновления и скопируй содержимое в существующую папку studentconnect с заменой. Свои .env и node_modules не удаляй. Новых зависимостей нет.
3. Загрузи в GitHub содержимое распакованного обновления (папку apps и корневые файлы), не ZIP. Важно загрузить и apps/api/prisma/migrations/20261018195000_chat_safety/migration.sql. Старые миграции оставь без изменений.
4. Render автоматически соберёт приложение, сгенерирует Prisma Client и применит новую миграцию через npm run deploy:start. Если автозапуск выключен, Manual Deploy → Deploy latest commit. Тариф Free и MAIL_MODE=manual остаются прежними. Секрет DATABASE_URL не меняй.
5. Дождись Live и обнови вкладки сайта у себя и друга. При ошибке пришли последние строки лога без секретов. Базу не сбрасывай, повторно создавать сервис не нужно.

Для локального запуска после копирования (это относится к DATABASE_URL локальной базы, а не автоматически к Neon):

```powershell
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run dev
```

## Возможности

- Кнопка «Смайлики» вставляет Unicode-эмодзи в позицию курсора. Работает и обычная клавиатура телефона.
- Меню «•••» рядом с временем сообщения доступно нажатием и с клавиатуры.
- «Ответить» добавляет цитату. Ответ разрешён только на доступное сообщение текущего диалога.
- «Редактировать» доступно только у собственного сообщения. После сохранения появляется отметка «изменено». Текущий текст исходного сообщения отображается и в цитатах. Историю редакций пользователи не получают.
- «Удалить у себя» скрывает любое сообщение только для текущего аккаунта, в том числе на других устройствах. У собеседника оно остаётся. Отменить скрытие через интерфейс нельзя.
- «Удалить у всех» доступно только отправителю. Вместо текста отображается «Сообщение удалено», цитаты становятся недоступны. Содержимое сообщения очищается в БД; ID и время остаются для истории и корректных курсоров.
- Изменения синхронизируются у обоих собеседников через Socket.IO и резервное обновление. Обновление страницы и переподключение запрашивают актуальный текст.

## Блокировка

В публичном профиле и открытом чате есть кнопки «Заблокировать» и «Разблокировать». На странице «Мой профиль» есть список собственных блокировок.

При блокировке новые сообщения, создание диалога, редактирование сообщений, интерес в ленте и запросы телефона запрещены с обеих сторон. Пользователи исчезают друг у друга из поиска и ленты. Переписка сохраняется, её можно читать, скрывать у себя или удалять свои сообщения у всех. Доступ к телефону отзывается в обе стороны. Разблокирование НЕ восстанавливает старое разрешение телефона. Если блокировки взаимные, для возобновления общения каждый должен снять свою.

Профиль по прямой ссылке и общие мероприятия по-прежнему доступны: это ограничение личного общения, а не скрытый аккаунт или запрет участия в общих событиях. Пользователь может пожаловаться и после блокировки.

## Жалобы

«Пожаловаться» есть в публичном профиле, в меню чужого сообщения и на странице чужого мероприятия. Причины: аватарка, профиль, оскорбления, спам, угрозы, другое. Для сообщения/мероприятия причины об аватарке и профиле не показываются.

Жалоба доступна допущенному пользователю, требует CSRF, ограничена 10 отправками за 24 часа. Повторная отправка при сетевой ошибке не создаёт копию. Свои профили, сообщения и мероприятия пожаловаться не позволяют. Жаловаться на личное сообщение может только участник диалога; скрытые и удалённые сообщения недоступны для новой жалобы.

Сохраняется копия указанного профиля (включая аватар), сообщения или мероприятия на момент жалобы. Если автор впоследствии изменит или удалит содержимое, копия в жалобе остаётся для рассмотрения владельцем проекта. Копия не публикуется и не рассылается собеседнику. Обычные пользователи не имеют API для просмотра чужих жалоб. Автоматического бана или удаления по факту жалобы нет. Проверяет владелец проекта вручную.

## Просмотр жалоб владельцем

Используется та же ADMIN_DATABASE_URL, что и для ручного допуска тестировщиков. Если переменная очищена, в терминале корня проекта сначала задай её:

```powershell
$secureConnection = Read-Host 'Вставь строку подключения Neon' -AsSecureString
$env:ADMIN_DATABASE_URL = [System.Net.NetworkCredential]::new('', $secureConnection).Password.Trim()
```

Вставь строку подключения в скрытый запрос, не в текст команды. Далее:

```powershell
npm.cmd run safety:reports
```

Показывает до 50 последних открытых жалоб. Для деталей (замени номер):

```powershell
npm.cmd run safety:reports -- --id НОМЕР_ЖАЛОБЫ
```

Детали содержат исходный текст или аватар жалобы. Не отправляй такой вывод в публичные чаты. Чтобы пометить рассмотренной:

```powershell
npm.cmd run safety:reports -- --id НОМЕР_ЖАЛОБЫ --resolve
```

Эта команда только меняет статус жалобы. Она не блокирует аккаунт и не удаляет содержимое. Панель модератора и административные санкции в эту версию не входят. Все статусы можно вывести так:

```powershell
npm.cmd run safety:reports -- --status ALL
```

Когда закончил:

```powershell
Remove-Item Env:ADMIN_DATABASE_URL
$secureConnection = $null
```

## Проверка вдвоём

1. Отправь текст с эмодзи с компьютера на телефон. Ответь на него.
2. Исправь исходное сообщение: текст и цитата должны обновиться у обоих. Перезагрузи вкладки и проверь снова.
3. Скрой входящее сообщение у себя: оно остаётся у автора, у тебя не возвращается после обновления. В ответах на скрытое сообщение его текст не показывается.
4. Отправь новое сообщение, попроси друга пожаловаться на него, затем удали своё сообщение у всех. В чате текста уже нет, копия в жалобе доступна владельцу.
5. Заблокируй друга. Оба не могут отправлять новые сообщения и запросы телефона; история видна. В поиске/ленте вас нет друг у друга. Сними блокировку: отправка снова доступна, старый доступ к телефону не возвращается.
6. Отправьте отдельные жалобы на аватар/описание профиля и мероприятие. Проверь их командой safety:reports.
7. Выйди из аккаунта: стартовый экран больше не показывает технические статусы и список этапов.

Полноценное ручное испытание на конкретных телефонах нужно выполнить после публикации. Автотесты на изолированной PostgreSQL WASM не заменяют проверку параллельных транзакций на настоящих отдельных PostgreSQL-соединениях.
