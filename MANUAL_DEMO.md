# Закрытое демо без почтового сервиса

Для этого варианта используется MAIL_MODE=manual. Это ручной допуск знакомых тестировщиков, а не доказательство владения почтой. Попроси друга подтвердить указанный адрес в вашем личном общении. Письма и ссылки подтверждения не отправляются и не печатаются в логах. Пароли, сессии, CSRF и запрет доступа неподтверждённым аккаунтам сохранены. Публичной команды допуска через HTTP нет.

## Render

Обнови render.yaml из этого комплекта в GitHub. На странице создания Blueprint обнови вкладку: MAIL_MODE должен стать manual, поля BREVO_API_KEY и BREVO_SENDER_EMAIL должны исчезнуть. Остаётся только секрет DATABASE_URL (строка Neon). Если поле опустело после обновления, вставь строку заново непосредственно из Neon. Blueprint Name: studentconnect, Branch: main, план Free. Затем Deploy / Apply. Не создавай второй сервис, если один уже создан: измени MAIL_MODE на manual в его Environment, удали пустые переменные BREVO_API_KEY/BREVO_SENDER_EMAIL и запусти новый deploy.

База Neon новая, аккаунты из локальной Docker-базы автоматически не переносятся. Существующая локальная база не меняется. Не удаляй свои .env и не сбрасывай базы.

## Ручной допуск из PowerShell на своём компьютере

Обнови локальный проект этими же файлами. Зависимости не менялись. Если node_modules уже установлены, повторный npm ci не нужен. В новом терминале VS Code в корне проекта:

```powershell
npm.cmd run db:generate
$secureConnection = Read-Host 'Вставь строку подключения Neon (ввод скрыт)' -AsSecureString
$env:ADMIN_DATABASE_URL = [System.Net.NetworkCredential]::new('', $secureConnection).Password
```

Вставь НОВУЮ актуальную строку Neon в скрытый запрос терминала. Не набирай пароль непосредственно в командной строке: так он не останется в истории команд. Секрет не нужно записывать в GitHub или .env. Команда допуска намеренно НЕ использует обычную DATABASE_URL из локального .env, чтобы не подтвердить пользователя случайно в другой базе.

Друг регистрируется на публичном сайте и видит «Ожидается допуск к демо». Уточни у него адрес при регистрации и выполни (замени friend@example.com):

```powershell
npm.cmd run users:approve -- --email friend@example.com --confirm
```

Скрипт покажет адрес хоста/имя базы без пароля и результат approved:true. Аккаунт должен уже существовать в этой базе. Регистрировать или подтверждать все аккаунты сразу скрипт не умеет. Повторное подтверждение безопасно, changed:false означает, что аккаунт уже допущен. Старые токены подтверждения этого аккаунта удаляются. Пароли/сообщения/другие пользователи не меняются.

После команды друг нажимает «Проверить допуск» на сайте. Твой собственный новый аккаунт нужно допустить таким же способом.

Закончив, очисти переменную и закрой терминал:

```powershell
Remove-Item Env:ADMIN_DATABASE_URL
$secureConnection = $null
```

Для открытого запуска позже нужен реальный почтовый сервис. Не переключай production в console: этот режим по-прежнему запрещён. Для SMTP/Brevo поддержка сохранена, но на Render Free следует использовать HTTPS API почтового сервиса.
