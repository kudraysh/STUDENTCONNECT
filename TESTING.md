# StudentConnect 0.8.0 — проверка с 3–5 тестировщиками

Этот файл — план ручной проверки. Пустой результат не означает успех. Автоматические результаты находятся в TEST_RESULTS.md.

## Подготовка

- A — организатор и владелец телефона; B и C — участники; D/E — дополнительные студенты для ленты и проверки изоляции.
- Каждый создаёт собственный аккаунт, подтверждает почту и выбирает интересы. В локальном режиме ссылки подтверждения видит разработчик в терминале «ТЕСТОВАЯ ПОЧТА». Каждому передаётся только его ссылка.
- Для нескольких аккаунтов на одном компьютере используй разные браузеры/профили или приватную вкладку. Смешанные вкладки одного браузерного профиля разделяют cookie.
- Работают Docker Desktop, сайт и ngrok. Все тестировщики используют один текущий HTTPS-адрес. При изменении адреса нужно обновить WEB_ORIGIN и разрешённый домен Vite, затем перезапустить сайт.
- Для ngrok: TRUST_PROXY=1 в apps/api/.env. Адрес WEB_ORIGIN — HTTPS-ссылка без пути и завершающего слеша. Подробные команды — UPDATE.md.
- Зафиксируй браузер, устройство и версию приложения 0.8.0. Начни с A на компьютере, B на телефоне Safari/Chrome, C на другом компьютере. D/E подключаются одновременно для сообщений и ленты.
- На реальных тестовых аккаунтах не удаляй базу/том Docker и не изменяй даты свайпов ради теста. Возврат пропущенной карточки через 7 дней уже покрыт автоматической проверкой.

## Сценарии

В последней колонке запиши «ОК» либо номер отчёта об ошибке и устройство. Важно проверять ожидаемое поведение, а не только отсутствие сообщения об ошибке.

| № | Кто и что делает | Ожидаемый результат | Результат |
|---|---|---|---|
| 01 | B регистрируется, подтверждает почту; повторно открывает ту же ссылку | Первый переход подтверждает почту; повтор не создаёт второй аккаунт и сообщает об использованной ссылке | Не проверено |
| 02 | B выходит, вводит неверный пароль, затем правильный | Неверный вход отклонён, правильный открывает собственный аккаунт | Не проверено |
| 03 | A меняет имя, описание, интересы, фото; обновляет страницу | Сохранённые значения остаются; фото отображается, неверный формат/большой файл объясняются ошибкой | Не проверено |
| 04 | B открывает профиль A | Видны публичные имя, фото и интересы; email и номер телефона не видны | Не проверено |
| 05 | A ищет B по имени, группе и интересам, меняет сортировку | Результаты соответствуют фильтрам; после сброса доступны другие студенты | Не проверено |
| 06 | A открывает «Люди → Лента», делает 2 выбора | Фото/инициалы, имя и интересы видны; обучение исчезает после двух сохранённых выборов и не возвращается после обновления | Не проверено |
| 07 | A свайпает B вправо | B получает одно уведомление с профилем A; в профиле можно нажать «Написать» | Не проверено |
| 08 | A свайпает C влево и обновляет страницу | C отсутствует в ленте A, но доступен в общем каталоге; C не получает уведомление | Не проверено |
| 09 | На телефоне B вертикально прокручивает длинную карточку и делает маленькое горизонтальное движение | Вертикальная прокрутка и короткое движение не выбирают человека | Не проверено |
| 10 | A создаёт мероприятие на 2 человека (организатор входит в лимит); B и C подают заявки | Заявки видит только организатор; до принятия они не занимают место | Не проверено |
| 11 | A рассматривает обе заявки в двух вкладках почти одновременно | Принимается только один из B/C; число участников не превышает 2; второй получает понятную ошибку | Не проверено |
| 12 | A отклоняет заявку; участник подаёт новую | Отклонение уведомляет адресата; новая заявка возможна до начала/закрытия и при свободных местах | Не проверено |
| 13 | На отдельном мероприятии B вступает, выходит, вступает повторно и выходит второй раз | После второго выхода третье вступление запрещено, счётчики относятся только к этому мероприятию | Не проверено |
| 14 | На другом мероприятии A исключает B с причиной | B видит причину, получает уведомление и не может вступить повторно в это мероприятие | Не проверено |
| 15 | A закрывает мероприятие с участником и ожидающей заявкой | Нуждается в подтверждении; участники сохраняются, заявка отклоняется, адресаты уведомляются | Не проверено |
| 16 | B пробует подать заявку/выйти со старой страницы закрытого мероприятия | Сервер отклоняет действие; после обновления виден статус «Закрыто» | Не проверено |
| 17 | A/B/C/D одновременно переписываются в разных диалогах | Сообщения приходят своим адресатам; чужая переписка не появляется | Не проверено |
| 18 | A отправляет текст с переносами и строкой `<b>Привет</b>` | Отображается обычный текст, не HTML; после перезагрузки история сохраняется | Не проверено |
| 19 | B отключает интернет, пытается отправить сообщение, затем возвращает связь и повторяет | Черновик не пропадает при ошибке; повтор сохранённой отправки не создаёт дубликат; история догружается | Не проверено |
| 20 | B читает входящее сообщение при открытом чате | Счётчик сообщений уменьшается, соответствующее уведомление становится прочитанным | Не проверено |
| 21 | B запрашивает номер A; A отклоняет, затем после минуты B повторяет и A разрешает | До разрешения номера нет; после него номер виден только B в этом диалоге | Не проверено |
| 22 | A отзывает разрешение, затем меняет/удаляет номер в профиле | API больше не отдаёт номер B; открытый диалог скрывает его при обновлении доступа. Уже скопированное число удалить у другого человека невозможно | Не проверено |
| 23 | B открывает колокольчик, фильтр непрочитанных и отмечает показанные | Список и счётчик согласованы; после перезагрузки отметки остаются | Не проверено |
| 24 | B открывает уведомление об интересе, мероприятии и телефоне | Каждый переход ведёт к правильному профилю, мероприятию или диалогу | Не проверено |
| 25 | B отправляет один отчёт через «Сообщить об ошибке» внизу сайта | Показывается номер; отчёт виден в истории B и локальной команде разработчика | Не проверено |
| 26 | C открывает «Мои отчёты» | Отчёт B отсутствует; не видны чужие email, телефоны и данные отчёта | Не проверено |
| 27 | Разработчик меняет статус отчёта B на RESOLVED в Prisma Studio; B обновляет историю | Статус становится «Исправлен» только у этого отчёта | Не проверено |
| 28 | На телефоне и компьютере меняют светлую/тёмную тему, открывают профиль, ленту, сообщения и отчёты | Текст читается, элементы не обрезаются, кнопки доступны, нижняя навигация не закрывает содержимое | Не проверено |
| 29 | A/B обновляют страницы и перезапускают сервер без сброса базы | Профили, переписка, мероприятия, решения ленты, отчёты и отметки чтения сохраняются | Не проверено |

## Если нашли ошибку

Внизу сайта нажми «Сообщить об ошибке». Укажи раздел, путь страницы (без полного URL/параметров), краткое название, шаги, ожидаемое и фактическое поведение; желательно устройство/браузер. Не вставляй пароли, токены или переписку других людей. Сохрани номер отчёта в колонке «Результат».

Если сайт вообще не открывается, запиши те же данные отдельно и передай разработчику после восстановления. Поломанная загрузка JavaScript может не позволить открыть форму; React-заглушка не заменяет диагностику сетевой ошибки.

## Как разработчик смотрит отчёты

Из папки studentconnect:

```powershell
npm.cmd run feedback:list
npm.cmd run feedback:list -- --status ALL --limit 50
npm.cmd run feedback:list -- --id НОМЕР_ОТЧЁТА
```

Команды работают локально с apps/api/.env и не отправляют отчёты во внешние сервисы. Первая показывает до 20 открытых отчётов, --id — подробности одного.

Чтобы отметить исправление, открой отдельный терминал из папки studentconnect:

```powershell
cd apps/api
npx.cmd prisma studio
```

В таблице FeedbackReport найди id, поменяй только status с OPEN на RESOLVED и сохрани. После этого повтори шаги ошибки и запиши результат. Обычные пользователи не могут менять статусы через сайт. Не запускай отдельный туннель к Prisma Studio.

## Что считать завершением проверки

Все применимые строки проверены хотя бы одним человеком, мобильные сценарии — на телефоне, результаты записаны, блокирующие ошибки исправлены и повторно проверены. Подключение 3–5 людей по плану пока не является выполненным нагрузочным тестом.
